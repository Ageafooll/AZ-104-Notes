
**Azure App Service** has everything you need to create websites, mobile backends and web APIs. It's a PaaS that lets your app tun and scale with ease.
Things to consider when creating one is:
- **Name** - Should be unique since you'll have a unique URL.
- **Region** - Must be in the same region with your **App Service Plan**.
- **Pricing plans** - Our app needs to be asspciated with one to establish available resources, features and capacity.

When we deploy an app, we can use a seperate **deployment slot**(staging slot) instead of the default production slot. 
Deployment slots have their own hostnames(click and go to their blade). They are available in different amount in Standard, Premium, Isolated pricing tiers. App content and configuration elements can be **swapped** between two deployment slots. There is also **Auto swap** feature that everytime you push to a slot, App Service automatically swaps the app into production after it is warmed up.

When you swap, some settings are **slot-specific**(it remains in source slot) and some are **swapped settings**(swapped between slots). You can check which are which from learn.microsoft -> App Service -> Deployment and configuration -> deployment methods -> create staging environments

There is a **authentication and authorization security module** that can handle authenticating users with the specified IdP, validate, store and refreshing tokens, managing authenticated sessions and injecting identity info into request headers. Without you having to make changes into your application code.

You may **Allow Anonymous requests** or **Allow only authenticated requests**(redirect all anonymous to IdP you choose). Also see authentication and authorization traces in our log files.

We can also add a **custom domain name** to our app service. (Like www.agea.com instead of myapp-313131.westus.azurewebsites.net). Steps to do it are following:
1. Reserve our domain name either from a domain registrar or directly from azure "App Service Domains" resource.
2. Map our custom domain name to the azures provided domain name with a CNAME record.
3. Validate the domain name and add it to our web app.

You can configure manual or scheduled **Backups** for our app (At least Basic pricing tier). We can restore a snapshot of a previous state. We can backup app config settings, file content, and any database connected to our app. We can do full backups or partial backups, you restore them in the same way. They are saved to a container in a storage account(must be in the same region)(not some type of backup or recovert services vault).

Considering request rates, dependency rates, response times, failure rates, exceptions etc.

These are the steps to configure **TLS Certificates** for the app service:
1. Secure a certificate through a **CA**, could be **Azure's managed certificates**.
2. Add the **custom domain** to App Service.
3. In **TLS/SSL settings** blade, upload PFX file or select managed certificate. Assign it to custom domain using the binding. Optionally store the cert in **Azure Key Vault** for centralized control.
4. Verify that protocol is set to HTTPS.

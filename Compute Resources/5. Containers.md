
While virtual machines virtualizes the hardware, **containers** virtualize the operating system. Here are the comparison to decide which one to use:

| Container                                                                       | Virtual Machine                                                                           |
| ------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| Lightweight isolation.                                                          | Complete isolation from the ost OS and other VMs. Strong security boundary.               |
| User mode portion of OS. just needed services used, fewer system resources used | Runs complete OS including kernel, more system resources used.                            |
| Azure Disks used for local storage or Azure Fİles (SMB shares) for shared       | Virtual hard disk(VHD) for local storage or SMB file share for shared by multiple servers |
| If fails, orchestrator rapidly creates another one.                             | If fails, it can fail over to another server and OS restarts.                             |
**Azure Container Instances (ACI)** is the simplest way to run containers in Azure. You can pull an **image** for the container from **Azure Container Registry (ACR)** or docker hub. Size choices are more flexible:
![[Pasted image 20260809133301.png|627]]

A container image created in Windows requires a Windows-based host and won't run in Linux vise versa because of kernel features.

You can expose you containers to internet or to a vnet from Network settings and choose a DNS name, if its public you'll have a public ip too:
![[Pasted image 20260809133541.png|410]]

**Container group** is the top-level resource of ACI, it is a collection of containers that share a lifecycle, resources, local network and storage volumes and scheduled on the same host machine. It is similar to a Kubernetes pod. (Multi container group can't be deployed on portal and must use another method like ARM template or YAML files):
![[Pasted image 20260809135710.png|533]]
It is useful for scenarios like one container serves the web app and another one pulls the latest content from source control. or one container is a monitoring container.

**Azure Container Apps (ACA)** is a **serverless** platform allows you to less care about the infrastructure while running containarized apps. It is built on Azure Kubernetes Service (AKS) and provides automatic scaling on resources based on HTTP traffic, CPU load, any KEDA-supported scaler etc. You don't manage kubernetes itself it is abstracted.
It is useful for apps that span many microservices, kubernetes-style apps.

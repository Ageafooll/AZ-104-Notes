
Microsoft **Entra ID** is a PaaS for **managed** directory services. It's a cloud-based identity and access management service. It is used for managing identities, enforcing access policies and securing applications and data in cloud and on-premises. (**single sign-on (SSO)**, **multifactor authentication (MFA)** etc..)

It is not simply **Active Directory Domain Services** in cloud, they operate different. **AD DS** is a directory service for storing directory data (like user accounts, password) and make it available for network users, administrators and other devices and services. It runs as a service on **Windows Server** referred to as a **domain controller** (physical or virtual server).

A **tenant** in Entra ID is a dedicated instance of the identity service that represents our organization, it is a secure container for user accounts, groups and app registrations. When you sign up for a Microsoft cloud service like **Azure** or **365** it is automatically created. Unlike AD DS, Entra ID is multi-tenant and ensures isolation between its individual directory instances. An **Azure Subscription** must be associated with one and only one tenant. Each tenant is assigned a default **DNS domain name** which ends with .onmicrosoft.com. though adding a custom domain name for a tenant is common.

It's schema contains a **flat structure** and doesn't has **Organizational Units (OU)** like AD DS which means it doesn't has **Group Policy Objects (GPO)** either so you have to use something else to manage computer and user settings like **Microsoft Intune** which is a **Mobile Device Management (MDM)** tool.

An application in in Entra ID is represented with **Application** and **Service Principal** objects. Application class is in the **home tenant** and is a blueprint for its definition. Service Principal is the runtime **identity (security principal)** that can hold permissions and access resources which is created when a client tenant signs up for the app (Like using Slack for your tenant which is created by another company). They are seen in **Enterprise Applications** menu (except **managed identities**). When you register an app it creates both an Application and Security Principal object. 

Table below Shows some differences between Entra ID and AD DS:

|                                 | Entra ID                                                                                        | Active Directory Domain Services                                                         |
| ------------------------------- | ----------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Structure                       | flat-structure                                                                                  | hierarchical X.500-based                                                                 |
| Protocols                       | uses **REST API**, **SAML**, **OAUTH**, **OpenID Connect** over **HTTP/HTTPS**                  | uses **LDAP**, **Kerberos**                                                              |
| Objects                         | includes devices that Entra joined or registered under "All devices"                            | includes computer objects representing computers that join the domain                    |
| Discovering resources, services | uses **HTTP/HTTPS** protocols with hardcoded URLs (like domain suffixes or Microsoft Graph API) | uses **DNS**, specifically **SRV (Service) record**s like "_ldap._tcp.dc._://domain.com" |

 Different Entra ID plans like **Free**, **P1**, **P2** provides different functionalities. 
 P2 license provides **Microsoft Entra Identity Protection** and **Microsoft Entra Privileged Identity Management** unlike others. You may check all the functionalities in learn.microsoft --> identity --> Entra ID --> Licenses

**Entra Domain Services** provides domain services such as Group Policy, domain joining, Kerberos, LDAP etc. on cloud for applications that rely on AD DS domain services like most of the line-of-business (LOB) applications. 
It provides managed DCs, you don't have to replicate a local domain server to cloud. Data is replicated from Entra ID. 
It is configured by dedicating a subnet for Entra DS in a vnet,  enabling the service, updating DNS for the vnet and joining the application in vnet to domain.

Some limitations of it can be found in learn.microsoft --> identity --> Entra Domain Services

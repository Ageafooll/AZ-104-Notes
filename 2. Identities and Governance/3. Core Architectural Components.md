
**Azure Cloud** itself is the set of cloud services by Microsoft with a massive global network

To create and use services in Azure you need an Azure subscription, when you create an Azure account a subscription is created for you.

An **Azure Account** represents the agreement signed between Microsoft and you. It is a contract and billing container that is tied to a top-level administrative identity. There are different billing account types and subscription types(offers). 

Azure's core architectural components can be broken down to **physical infrastructure** and **management infrastructure**.

The **physical infrastructure** starts with **datacenter**s these are facilities with servers, with dedicated power, cooling and networking infrastructure (you don't interact with individual datacenters directly).

**Geography** is data residency and compliance boundary. (US, Europe etc..)

A **region** is a geographical area on the planet that contains at least one datacenter.  You choose a region for some resources. (some services are only available in certain regions)

**Availability Zones** are physically separate datacenters within an region. It provides resiliency by having independent power, cooling, network. Stateful data is replicated synchronously. They are connected to each other high-speed networks.

**Region pairs** within a geography, provides resiliency against events such as natural disasters, power outages that affect an entire region. It replicates stateful data asynchronously so services would fail over to the other region. (not all services automatically replicate or fall back). Planned Azure updates are rolled out to paired regions one region at a time.

**Sovereign region**s are instances of Azure that are isolated from the main instance for compliance and legal purposes (US Gov, China).

The **management infrastructure** is the hierarchy of resources, resource groups, subscriptions and management groups. These help you organize resources, control who can access what and manage costs.

A **resource** is a basic building block, anything we create, provision or deploy is a resource (VMs, databases, virtual networks etc.).

**Subscription**s are a unit of management, billing and scale. An Azure subscription links to an Azure account. Different subscriptions can have different billing models and access policies.
- **Billing boundary** - Determines how an Azure account is billed, separate billing reports and invoices are generated for each subscription
- **Access control boundary** - You can apply access-management policies at the subscription level that spans resource groups.

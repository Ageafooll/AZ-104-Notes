
Azure **service endpoints** and **private endpoints** are both used for connecting our virtual networks securely to Azure **PaaS**s (Storage, Key Vault, Databases, App Service etc.). without routing data over the public internet (through Microsofts network backbone). they work in different ways.

A **service endpoint** extends our VNet identity to the Azure Service, service still uses its public ip and you enable access through services firewall and choosing the subnet and requires no DNS changes. (They can be in the same region or not depending (SQL should be in same region)) A storage account one would be like this:

3. Now when we can reach the storage account from the VMs subnet but not from outside that subnet, it'll have a public ip:![[Pasted image 20260813184850.png]]

A thing to consider is if we can access from on-premises. We can not access service endpoint from on-premises over a VPN/ExpressRoute (because it keeps its public ip and our routers doesn't knows the traffic should go through the vnet to access it) but we can with private endpoints.

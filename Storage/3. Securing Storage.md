
We use different strategies to ensure data is secure. Some of these are **Encryption at rest**, **Encryption in transit**, **Encryption models**, **Authorizing requests**, **RBAC** and **Storage analytics**.

Following strategies are for **authorizing requests** to Azure Storage:
- **Microsoft Entra ID** - RBAC for users, groups or applications.
- **Shared Key** - Account access key, an account has key two keys, you may disable this for enforcing Entra ID
- **Shared access signatures** - SAS delegates access to a resource with specified permissions and time interval
- **Anonymous access to container and blobs** - We talked about this in previous module.

**Shared access signature (SAS)** is a URI that grants restricted access to storage resources. It is signed by an account key. They can be used in different scopes (account-level, file share scope, object-level etc.):
- **User Delegation SAS** - Secured using Entra ID instead of storage account key. RBAC
- **Service SAS** - access to a specific service and specific container, table etc.
- **Account SAS** - storage account level, allows high-level storage administrative operations.

If you restricted public network access, even though if you have a SAS you can't access it if you aren't in a specific vnet or ip address. Network, Firewall rules are checked first.

It is passed with the parameters in the URI like the following:

In Azure Storage, data at rest in encrypted by default (you can't disable it) with Storage Service Encryption (SSE) with a 256-bit Advanced Encryption Standards (AES) cipher. It is encrypted and decrypted on the go in background. You configure it from here:

**Infrastructure Encryption** can be enabled for the storage account, data is encrypted twice once at the service level and once at the infrastructure level with two different algorithms and keys.

**Platform-managed keys (PMKs)** are the encryption keys generated, stored, managed by Azure. You don't interact with these and these are used for default.

**Customer-managed keys (CMK)** are keys read, created, administrated, rotated by one or more customers. Keys are stored in a customer-owned **key vault** or hardware security module (HSM). Used in Bring Your Own Key (BYOK) scenarios for compliance.

**Storage insights** provides monitoring for storage accounts. Has metrics, logs. Shows performance, capacity, availability. You can track usage. Useful for audits.

**Microsoft Defender for Storage** provides you Malware scanning, sensitive data threat detection, Activity-based threat detection.

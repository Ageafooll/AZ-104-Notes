**Blob Storage** is optimized for storing massive amounts of unstructured data. Objects in Blob storage can be accessed from anywhere via HTTP or HTTPS. By enabling hierarchical namespace in storage account you can use SFTP too. It is ideal for serving data directly to a browser, streaming data and storing data for backup and restore.

**Azure Files** support highly available network file shares with **SMB** or **NFS**. Can be used to migrate On-premises apps that uses file shares. Or sharing configuration files. **Storage account credentials (Access keys, SAS Tokens, Identity)** lets users access the file share and mount them.

**Standard** storage accounts are backed by **magnetic hard disk drives (HDD)** and is lower cost. Would be used for bulk storage or when data is infrequently accessed.
**Premium** storage accounts are backed by **solid-state drives (SSD)** and offers low-latency performance. Can be used for VMs with I/O-intensive applications (like databases).

Every object you store in Azure Storage has a **unique URL address**, that's why you need to give a unique name to your storage account. The default endpoint for an Azure File service might look like "//mystorageaccount.file.core.windows.net" and for accessing a data in a container might use the following URL address: "//mystorageaccount.blob.core.windows.net/mycontainer/myblob".

You can configure a **custom domain name** for your storage account with these steps:
1. Create a **CNAME record** in our domain provider like "assets.example.com" to "mystorageaccount.blob.core.windows.net".
2. From our storage account -> Security + networking -> Networking -> Custom domain, you enter the full custom domain name and verify it (It only supports HTTP by default. If you want HTTPS too you need to use **Azure Front Door** too)

You can check the "Default to Microsoft Entra authorization in the Azure portal" option to use identities in Entra ID with RBAC for access in portal before SAS or keys(you can disable keys and SASs after enabling this). Owner role doesn't grants data plane permissions, if you enabled it you must have a data plane role too.

To secure access to storage endpoints you can configure **service endpoints** or **private endpoints** which can be used for other PaaS(Databases, Key Vaults) too. We will talk about this in Networking unit.


Bicep is an **Infrastructure as Code (IaC)** tool in domain-specific language (DSL) created by Microsoft.  It transpiles into JSON **Azure Resource Manager (ARM) Template** when it is deployed.

Optionally if you want to specify which subscription to deploy by default you do(else it'll use default sub):

```
Get-AzSubscription
Set-AzContext -SubscriptionId {Your subscription ID}
```

Next to keyword **resource** there is the symbolic name to refer to the resource in bicep (not its actual name in Azure). You can reference its properties in the file. Next to it there is resource type and API version. 

By referencing another resources symbolic name in another resource
(appServicePlan.id), Azure understands the implicit dependency between them.

---

You can use **parameters** to bring values from outside like in ARM template, you may give a default value too, you specify its type (better for the things that might change for each deployment).

A **variable** is defined and set in the file and has to have a value (better when you use same values for each deployment).

An **expression** is useful when you want to discover values of parameters or variables when the file runs, like "resourceGroup().location".

```
uniqueString(seed)
```
returns a string by the seed (is useful when you need unique names for resources)

```
resourceGroup().id
```
Returns unique rg id (a resource ID is a unique identifier for each resource which includes subscription id and rg name).

You can specify allowed values for parameters with "@allowed" and make useful things with ternary operators like the following code and deployment, you can specify the deployment mode too:

```
param location string = 'swedencentral'
param storageAccountName string = 'toylaunch${uniqueString(resourceGroup().id)}'
param appServiceAppName string = 'toylaunch${uniqueString(resourceGroup().id)}'

@allowed([
  'nonprod'
  'prod'
])
param environmentType string

var appServicePlanName = 'toy-product-launch-plan'
var storageAccountSkuName = (environmentType == 'prod') ? 'Standard_GRS' : 'Standard_LRS'
var appServicePlanSkuName = (environmentType == 'prod') ? 'P2v3' : 'F1'

resource storageAccount 'Microsoft.Storage/storageAccounts@2023-05-01' = {
  name: storageAccountName
  location: location
  sku: {
    name: storageAccountSkuName
  }
  kind: 'StorageV2'
  properties: {
    accessTier: 'Hot'
  }
}

resource appServicePlan 'Microsoft.Web/serverfarms@2024-04-01' = {
  name: appServicePlanName
  location: location
  sku: {
    name: appServicePlanSkuName
  }
}

resource appServiceApp 'Microsoft.Web/sites@2024-04-01' = {
  name: appServiceAppName
  location: location
  properties: {
    serverFarmId: appServicePlan.id
    httpsOnly: true
  }
}
```

**Outputs** are like in ARM templates used for when the human or tool that did the deployment needs some data back from the file after deployment. Might be like:
```
output appServiceAppHostName string = appServiceApp.properties.defaultHostName
```

**Bicep Modules** allows us to organize and reuse bicep code. A bicep file is the module

After **module** keyword you specify symbolic name like in parameter. Then you specify the path of the bicep file to be used as module.

An **output** from one module can be parameter for its parent module.

The **parameters** you specify in main file can be used for the module

--- 

You can turn existing bicep file into ARM template with this command (transpilation):
```
bicep build main.bicep
```

Or you can turn existing ARM template into bicep with this command (it is best effort, doesn't guarantees the right result):
```
bicep decompile main.json
```

Bicep documentation can be found in learn.microsoft -->  Language and Tools -->  Bicep

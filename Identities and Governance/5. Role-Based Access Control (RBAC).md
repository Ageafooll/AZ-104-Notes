
**Azure RBAC** is an **authorization** system that helps you manage who has which access in what scope to Azure resources. **Microsoft Entra ID** and Azure RBAC work together for this.

Each Azure subscription is associated with a single Entra directory, it is used for **single sign-on (SSO)** and access management. Access is granted by assigning the appropriate **Azure role** to **users**, **groups** and **applications** at a certain **scope**(they are inherited top down. management group, subscription, rg etc.). To create a role assignment you need three elements: a **security principal**, **a role definition** and a **scope**. Azure RBAC supports distinct assignment for **control plane** and **data plane** operations. Like for a storage account, an assignment might have **Storage Account Contributor**(control on storage account itself, not read or write actual files or blobs inside account) or **Storage Blob Data Contributor**(read write delete blob containers and data without management of the storage account itself). Or for VMs **Virtual Machine Contributor**(control) or **Virtual Machine Administrator Login**(data).

This is how authorization and SSO works step by step:

1. User attempts to access a resource, if user doesn't has token the user is redirected to Entra ID, user authenticates to Entra ID (Azure trusts Entra ID).
2. Entra ID issues a short-lived **Access Token** and long-lived **Refresh Token**
    - **Access Token** - Is a **JSON Web Token** that contains claims about your identity and permissions. it is digitally signed by Entra ID (object id, expiration etc.) (RBAC permissions are not contained here).
    - **Refresh Token** - Is a long string of encrypted characters which Entra ID can decrypt, it contains User Identity, Device info etc.
3. You attach the **Access Token** to the header of the request and send it.
4. Azure resource extracts the token, verifies it and checks the identity inside it against **Azure RBAC rules** and the action is approved if you have the required role.
5. If your Access token expires, instead of asking you to log in again it sends the Refresh Token to Entra ID in background to get the Access token.

To see role assignments on a specific scope you click the **Access control (IAM)** blade on the resource, resource group etc. and see the following sections.
Check access, shows accesses of your user or a specific user, group or service on the scope
Role assignments, shows all the roles assignments in the scope. (job function, privileged administrator).
Roles, Shows the assignable roles in the scope and see how many people has the specific role
![[Pasted image 20260730150348.png]]

To add a role assignment for a scope, you click add and which role to assign to who(user, group, managed identity).
![[Pasted image 20260730150638.png]]

To remove role assignment just check the role assignment and delete.

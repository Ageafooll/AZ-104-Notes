
It is a storage service for storing large amounts of unstructured object data:
![[Pasted image 20260803213326.png|570]]

**Container** resource is used to group a set of blobs. All blobs must be in a container.
To configure a container you give it a name (must be unique within the storage account) and choose the **public access level** (what unauthenticated anonymous users can read):
 - **Private (Default)** - Prohibits anonymous access to the container and blobs.
 - **Blob** - Allow anonymous public read access for the blobs only
 - **Container** - Allow anonymous public read and listing the things in container
The blob and container access levels have no effect if you didn't enable **Allow Blob anonymous access** in storage account level.

**Access tiers** are for optimizing blobs to support a particular pattern of data usage. Can be configured in Settings -> Configuration in storage account for default or per blob. From top down operation cost increases but storing cost decrease. (Premium doesn't has tiers)
![[Pasted image 20260803214702.png]]
Retrieval latency on Archive can be lowered by choosing high priority option. 
If you delete cool or cold tier objects before the retention period there'll be a early deletion fee. (When it is deleted from soft delete state if it is enabled too)

**Lifecycle management** offers rule-based policy that allows you to transition your blob data to the appropriate access tiers or delete it. You can configure it storage account wide or per blob with filter set with if - then clauses.
It includes options for **versioning** and **snapshots** too
![[Pasted image 20260803215752.png]]
**Object replication** copies blobs in a container asynchronously to another container in a region you choose (doesn't needs to be the region pair) according to **replication rules** you configure in Data management -> Object replication.
Blob versioning must be enabled in both storage accounts and **change feed** (read-only transaction logs of changes stored inside the account, also needed for point-in-time restore) must be enabled in the source account. It doesn't supports snapshots. Source and target container doesn't need to have the same access tier. It is supported in gpv2 and premium block blob accounts.
![[Pasted image 20260803220437.png]]

There are three types of blob, after you create it you can't change its type:
- **Block blobs** - consists of blocks of data that are assembled to make a blob. Used for most scenarios by default.
- **Append blobs** - also consists of blocks but optimized for append operations. Used for logging scenarios
- **Page blobs** - Can be up to 8 TB in size. Optimized for random access read/write operations. Azure VMs(system disks, data disks) and Managed Disks use it.

**Blob versioning** saves past versions of blobs automatically when it is updated. Unlike **snapshots** which you have to take manually (snapshots are supported in Azure Files too but not versioning).

**Soft delete** for blobs and containers enables you to recover deleted ones by retaining them for a period after deletion. You can configure how long to keep them for.


**Azure Files** offers fully managed file shares in the cloud, you can access file shares by using **Server Message Block (SMB)**, **Network File System (NFS)** and HTTP protocols. It is useful for lift and shift scenarios, shared application settings, storing tools and utilities that are needed for administering resources.

Here are some comparisons between Azure Files and Blob Storage

| **Azure Files**                                                                         | **Blob Storage**                                                                  |
| --------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| provides SMB, NFS, client libraries, REST interface                                     | provides client libraries, REST interface                                         |
| Files here are true directory objects                                                   | Blobs are a flat namespace                                                        |
| Data here is accessed through file shares                                               | Blob data is accessed through a container                                         |
| Ideal to lift and shift applications to cloud that already uses native file system APIs | Ideal for applications that need to support streaming and random-access scenarios |
A file share don't support both SMB and NFS at the same time. But different file shares in the same storage account can support one each.

Azure Files support different access tiers like blobs. Two storage tiers are premium (SSD-backed) and standard (HDD-backed). Top down access tiers are **Premium**(pay for capacity reserved), **Transaction Optimized**, **Hot**, **Cool**. (you can't change from standard to premium vice versa once the account is created)

For accessing Azure Files if you are using SMB / Mapped Drives there is two-layer permission. This is **SMB Identity based access/authentication**.
**Share-Level** controls who can access the file share itself with **RBAC** roles like "Storage File Data SMB Share Contributor".
**File/Directory-Level** enforces granular rwx permissions on specific folders and files with **NTFS ACLs**. You must have a Line of Sight to **Microsoft Entra Kerberos**, **AD DS** or **Entra Domain Services** to resolve identities. (permissions are edited before by an administrator from properties -> security on files).

**Access key**s and **SAS** bypasses NTFS ACLs.

**Azure Storage Explorer** is a standalone application that lets you work with Azure Storage in multiple accounts and subscriptions.
You need both management and data layer permissions for full access with this. You may use keys for your own subscription or attach storage account or services with SAS for another Azure subscription.

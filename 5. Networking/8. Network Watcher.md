
**Azure Network Watcher** provides tools to monitor, diagnose, view metrics and enable and disable logs for network for Azure IaaS (VMs, VMSS, VNets, load balancers, application gateway). It isn't used for PaaS or Web analytics. When you create a IaaS it automatically creates a network watcher resource in the region (It must exist to use it within that region). Can be used in resolving connectivity issues related to IaaS, determining cross region network latencies etc.
They generally care about Azure fabric not things inside the guest OS.

**Topology** allows you to viusalize the network by showing all of the following resources in a VNet including the association between the resources and VNet (subnets, NICs, NSGs, LBs, VNet peering, VNet Gateway, VM, VMSS etc.)

**Connection Monitor** provides end-to-end connection monitoring which supports both hybrid and Azure cloud deployments. It can be used for measuring latency between resources, detecting changes that affect connectivity like changing a NSG, probing VMs at intervals to check failure, and diagnosing problems with providing explanations why that might have occured. You need to install agent (extension) on the hosts we want to monitor.

**IP flow verify** allows us to detect traffic filtering issues using 5-tuple packet parameter-based (local/remote port, protocol, local/remote IP) verification to detect if packets are allowed inbound/outbound in VM level. And tells us which security rule allowed or denied the traffic

**NSG diagnostics** allows us to detect traffic filtering issues too but it can do it in VM, VMSS, application gateway level. parameters can be IP address, IP prefix or a service tag. It tells us which security rule allowed or denied the traffic and allows us to add new security rule.

**Next hop** gets the next hop type and IP address of a packet from a specific VM and NIC, it also returns the associated route table with the next hop. Since effective routes are associated with a NIC.

**Effective security rules** allows us to view the all security rules applied to a NIC (sum of security rules on subnet and NIC level).

**Connection troubleshoot** checks the TCP connectivity between a source and destination VM(can be specified by FQDN, URI or IP address.) with a synthetic packet. It shows latency, hop count etc. and displays details about the fault if fails. It is a single point-in-time test unlike connection monitor which runs continiously in intervals.

**Packet capture** remotely captures raw packets in a session like Wireshark with filters. Captured data can be in a local disk or in a storage blob. We need an extension for this.

**VPN troubleshoot** enables us to troubleshoot virtual network gateways and their connections.

**Flow logs** allows us to log information about our Azure IP traffic flowing through a NSG or VNet and stores it in Azure storage. (They are not raw packets like packet capture. more like a brief who sent what to who).

**Traffic analytics** provides visualizations of flow logs data.

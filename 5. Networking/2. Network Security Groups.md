
We can limit network traffic to our resources in our VNet by using a **Network Security Group (NSG)** and assigning them to a subnet or a vNIC, and define **security rules** inbound and outbound.
You can assign one NSG to many but one subnet or vNIC can have at most one NSG assigned.

You define **security rules** in an NSG outbound/inbound to determine which traffic are allowed/denied. It's stateful on layer 4 so it is not like regular cisco ACLs, lower priority rules gets evaluated first.

When a single security rule contains multiple values in source, destination and service fields, it is called **augmented security rules**, reduces rule count.

**Service tags** represent a group of IP addresses prefixes from specific Azure service(usually PaaS or SaaS). If you applied NSGs on both subnet and vNICs they are evaluated independently, the combined set of all rules including vNICs, subnet and admin rules are called **efective security rules**. You view this with **Network Watcher** tools which'll be shown in another module.

Its useful to know even in intra-subnet traffic the NSGs in subnet level are evaluated twice for inbound and outbound (It's allowed by default).


**Unplanned hardware maintanance** happens when it is predicted that hardware is about to fail. Live migration is used to migrate VMs from failing hardware to healthy. It pauses VMs for a short time and performance might reduce before/after the event.

**Unexpected downtime** is when hardware fails unexpectedly. VMs are migrated to a healthy machine in same data center, VMs experience downtime (reboot) and might lose temporary drive.

**Planned maintenance** is periodic updates made by Microsoft to Azure platform. (your virtual machine OS or other software isn't updated. Underlying software host and hardware is patched)

**Update domain** is a group of nodes that are upgraded and rebooted together. Ensures only one update domain goes through it at a time. Protects against planned maintenance

**Fault domain** is a group nodes that represents a physical unit of failure (like same physical rack). Multiple fault domains mitigate against hardware failures, network outages, power interruptions etc. Protects against Unplanned maintenance and unexpected downtime.

**Availability set** lets you group related VMs that are deployed together in the same datacenter. These VMs are spread across multiple update domains and fault domains according to your configuration. Separate application tier should be in separate availability sets. You can add or remove VMs manually (should be added during creation, can't add existing one). You can add **Load Balancer** to distribute traffic within an availability set.

They can not span **availability zones** and can not **autoscale** unlike **VMSS**.

**Vertical scaling** AKA scale up, scale down, is changing the **size** of the VM. Its limit is the largest size. Is preferred when a legacy app expects a single server and local storage or need lower network overhead for caches and databases.

**Horizontal scaling** AKA scale out, scale in, is changing the **number** of VMs. It has fewer limitations and more flexible.

**Virtual Machine Scale Sets (VMSS)** is for deploying and managing identical(optional) VMs with **autoscaling** according to metric and schedule, and **zone redundancy**. Comes with native integration to load balancer or application gateway. (You configure the balancing) 

When implementing it you choose a **Orchestration mode** which are:
- **Flexible** - VMs can be identical or multiple type (size, spot) (you still can add VMs manually when creating).
- **Uniform** - VMs are all identical. (optimized for massive, identical scale. Including extensions and preventing configuration drift)
Then choose **image** and **size** like in a regular virtual machine.
